1System Overview

High-level architecture showing the three layers: mobile client, API server, and persistent database. Updated with MMKV for ride state persistence (C1 fix).

Three-Layer Architecture

The Ride Logging + Live Ride HUD spans three discrete layers:

  • Mobile Client (Expo 54 / React Native 0.81): GPS via expo-location + expo-task-manager with Accuracy.High (H6 fix), sensors via expo-sensors DeviceMotion, maps via @rnmapbox/maps (Mapbox Maps SDK v11 — premium styling, gradient polylines, 3D terrain; Expo config plugin, free tier 25k MAU), state via Zustand (scalars only) + MMKV (waypoints/routes, C1 fix) + Reanimated SharedValue (lean angle, C3 fix)
  • API Layer (NestJS 11 / Apollo GraphQL): New rides module, code-first schema, JWT auth via GqlAuthGuard, cursor-based pagination (H11 fix), waypoint quotas (H12 fix), client-supplied timestamps (H14 fix)
  • Persistence (Supabase PostgreSQL): rides + ride_waypoints tables with composite PK (H16 fix), full RLS policies including waypoints (C2 fix), triggers using public.update_updated_at (H7 fix), 30-day GDPR purge (H15 fix)

Key Fixes Applied (Overview)

  • C1: MMKV for waypoints/routes (not Zustand — iOS Keychain has 2048-byte limit)
  • C2: RLS policies on ride_waypoints using EXISTS subquery
  • C3: Lean angle via Reanimated SharedValue (not Zustand — no re-renders)
  • C4: Client-generated rideId in StartRideInput (enables offline sync)
  • C5: HUD redesigned for safety (speed 96pt, END RIDE long-press, 64pt touch targets, night mode)
  • H6: GPS Accuracy.High + 10m filter (not Balanced). Battery Saver toggle for Accuracy.Balanced
  • H7: Trigger function is public.update_updated_at() (not moat.set_updated_at())
  • H8: Admin check uses public.is_admin() STABLE function (not inline subquery)
  • H9: Battery drain table splits GPS-only vs Total System (screen is 8%/hr dominant consumer)
  • H10: Background task writes to MMKV (not Zustand — Android Hermes isolation)
  • H11: myRides uses cursor pagination on started_at (was OFFSET)
  • H12: Waypoint quota 10k/ride, rate limit 10 uploads/min/user, server-enforced
  • H13: No forced max brightness. Respect auto-brightness. Add Night Mode HUD variant
  • H14: Remove DEFAULT NOW() — client supplies started_at and endedAt
  • H15: 30-day hard-delete purge for GDPR (schedules after soft-delete)
  • H16: ride_waypoints PK is (ride_id, recorded_at) composite (eliminates UUID + index overhead)
  • H17: Auto-pause when speed=0 for 60s (RECORDING.STOPPED sub-state, excluded from moving time)
  • H18: paused_duration_s INT (was INTERVAL) + new auto_paused_duration_s

PRD Audit Fixes Applied (v2.1 → v2.2)

5 critical findings from the 4-agent PRD audit (Senior Engineer, Senior Architect, Product Manager, Motorcycle Domain Expert):

  • A1: First Ride Onboarding — permissions pre-prompt, "While Using" degraded mode, re-prompt strategy (Section 4b)
  • A2: Auto-pause uses position delta (<5m) + speed (<0.5 m/s) for 60s — not speed alone (Section 8)

  USING (

  ON public.ride_waypoints

  WITH CHECK (

      SELECT 1 FROM public.rides
      WHERE rides.id = ride_waypoints.ride_id
      AND rides.user_id = auth.uid()
    )

GDPR Hard-Delete Purge (H15 fix)

🔄 Scheduled Purge (runs nightly, 30 days after soft-delete) 
CREATE FUNCTION public.purge_soft_deleted_rides()
RETURNS void AS $$
BEGIN
  -- Hard-delete waypoints for rides deleted >30 days ago
  DELETE FROM public.ride_waypoints
  WHERE ride_id IN (
    SELECT id FROM public.rides
    WHERE deleted_at IS NOT NULL
    AND deleted_at < NOW() - INTERVAL '30 days'
  );

  -- Anonymize rides: null location PII
  UPDATE public.rides
  SET
    route_polyline = NULL,
    region = NULL,
    weather_snapshot = NULL
  WHERE deleted_at IS NOT NULL
  AND deleted_at < NOW() - INTERVAL '30 days';
END $$
LANGUAGE plpgsql;

Graceful Degradation: "While Using" Only Mode

If the user grants only foreground location (no "Always Allow"), rides still work but with limitations:

Capability Always Allow While Using Only
GPS recording with screen on ✅ ✅
GPS recording with screen locked ✅ ❌ (recording pauses)
HUD visible ✅ ✅ (keeps screen awake)
Crash recovery after app kill ✅ ❌
Foreground notification ✅ N/A

Show a persistent banner on the HUD: "Background location disabled — keep screen on for accurate tracking. Enable →"

Re-Prompt Strategy

  • iOS: After 3 foreground-only rides, show a nudge: "You've completed 3 rides! Enable background location for hands-free tracking." Link to Settings.
  • Android: Can request ACCESS_BACKGROUND_LOCATION directly. Show the pre-prompt again explaining the benefit.
  • "Not now" cooldown: Don't re-show the pre-prompt for 7 days after dismissal. Store dismissal timestamp in MMKV.

Implementation

📍 Permission Check on FAB Tap 
// PRD Audit Fix: Check + request permissions before starting ride

const checkAndRequestPermissions = async (): Promise<'full' | 'foreground_only' | 'denied'> => {
  const foreground = await Location.getForegroundPermissionsAsync();

  if (!foreground.granted) {
    // Show custom pre-prompt first, then request
    const userWants = await showPermissionPrePrompt();
    if (!userWants) return 'denied';

    const result = await Location.requestForegroundPermissionsAsync();
    if (!result.granted) return 'denied';
  }

  const background = await Location.getBackgroundPermissionsAsync();
  if (!background.granted) {
    const bgResult = await Location.requestBackgroundPermissionsAsync();
    if (!bgResult.granted) {
      // Foreground-only mode — ride works but no background tracking
      return 'foreground_only';
    }
  }

  return 'full';
};

// In FAB onPress handler:
const permLevel = await checkAndRequestPermissions();
if (permLevel === 'denied') {
  // Show "Location Required" bottom sheet with link to Settings
  return;
}

// Store permission level for HUD banner logic
rideStorage.set('ride.permission_level', permLevel);

// Proceed to bike picker → ride start
router.push('/(modals)/start-ride');
📱 Platform Notes

iOS 18+: "Always" location requires two separate grants — foreground first, then background (shown by OS after initial use, not immediately). The app must handle the interim state where foreground is granted but background is pending.

Android 14+: ACCESS_BACKGROUND_LOCATION must be requested separately from ACCESS_FINE_LOCATION. Cannot request both simultaneously.

Background Task (H10 fix: MMKV not Zustand)

🔄 Background Task Handler 
// H10 fix: Background task writes to MMKV, not useRideStore.getState()
// On Android, background task may run in separate Hermes instance

TaskManager.defineTask(BACKGROUND_TASK_NAME, async ({ data, error }) => {
  if (error) {
    console.error('Background GPS error:', error);
    return;
  }

  const { locations } = data as LocationTaskManagerEventResult;
  for (const location of locations) {
    -- Read rideId from MMKV (not Zustand)
    const rideId = rideStorage.getString('ride.current_id');
    if (!rideId) return;

    -- Append waypoint to MMKV buffer (not Zustand)
    const waypoints = rideMMKVUtils.getWaypoints(rideId);
    waypoints.push({
      latitude: location.coords.latitude,
      longitude: location.coords.longitude,
      altitude: location.coords.altitude,
      speed_mps: location.coords.speed ?? 0,
      heading: location.coords.heading ?? 0,
      accuracy: location.coords.accuracy ?? 0,
      recorded_at: new Date(location.timestamp).toISOString(),
    });
    rideMMKVUtils.saveWaypoints(rideId, waypoints);

    -- Update aggregates (min 50 pts or 30s before flush)
    if (waypoints.length >= 50) {
      await flushWaypoints(rideId, waypoints);
      rideMMKVUtils.saveWaypoints(rideId, []);
    }
  }
});

async flushWaypoints(rideId: string, waypoints: Waypoint[]) {
  try {
    const client = new GraphQLClient(...);
    await client.request(UPLOAD_WAYPOINTS_MUTATION, {
      input: { rideId, waypoints },
    });
  } catch (err) {
    -- Offline: keep in MMKV buffer, will retry when online
    console.warn('Waypoint sync failed, queued for retry');
  }
}

7Offline-First Architecture

Client generates rideId (C4 fix), background task uses MMKV (H10 fix), and client supplies timestamps (H14 fix).

Client-Generated Ride ID (C4 fix)

Problem: Offline rides generate UUID client-side. Waypoint batches reference this UUID. When startRide arrives on server, it generates a different UUID, orphaning all waypoint batches.

Solution: Client includes rideId in StartRideInput. Server inserts with this UUID.

💾 StartRideInput (C4 fix) 
// C4 fix: Client generates and supplies rideId to server

const startRide = async (motorcycleId?: string) => {
  const rideId = uuid.v4();  -- Client generates UUID
  const startedAt = new Date().toISOString();  -- H14 fix: client timestamp

  -- Save rideId to MMKV immediately (before server call)
  rideStorage.setString('ride.current_id', rideId);

  -- Optimistically update Zustand
  useRideStore.setState({
    status: 'recording',
    rideId,
    startedAt: Date.now(),
  });

  -- Try to create ride on server
  try {
    await client.request(START_RIDE_MUTATION, {
      input: {
        rideId,                -- C4: client-generated
        startedAt,             -- H14: client-supplied
        motorcycleId,
      },
    });
  } catch (err) {
    -- Offline: waypoints will queue with this rideId, retry on reconnect
    console.log('startRide offline, will sync when online');
  }
};

Sync Queue (MMKV-backed)

All mutations (startRide, uploadWaypoints, endRide) are queued in MMKV if offline. On reconnect, drain queue in order.

Scenario Behavior
Start ride (online) Immediate GraphQL call, rideId confirmed
Start ride (offline) Queue startRide mutation in MMKV, use generated rideId locally
GPS updates (online) Flush waypoint batches every 50pts or 30s
GPS updates (offline) Buffer waypoints in MMKV, queue uploadWaypoints batch
End ride (online) Flush remaining waypoints, call endRide mutation
End ride (offline) Queue endRide mutation in MMKV
Reconnect (online) Drain sync queue: startRide → uploadWaypoints* → endRide

8Auto-Pause & Moving Time Tracking

Speed < 0.5 m/s AND position delta < 5m for 60s enters RECORDING.STOPPED sub-state (H17 fix + PRD Audit A2). "Forgot to stop" auto-ends ride after 30 min (PRD Audit A3). Moving time excludes pause + auto-pause durations.

Auto-Pause Logic (H17 fix + PRD Audit Fix: Position Delta Confirmation)

Riders expect automatic pause at traffic lights, gas stations, and group ride waits. Don't stop GPS (user could resume), but exclude from "moving time".

🔧 PRD Audit Fix

Speed=0 alone is unreliable. GPS reports speed=0 during slow parking-lot maneuvering, lane filtering at walking speed, and duck-walking heavy touring bikes. Auto-pause now requires both speed < 0.5 m/s AND position delta < 5m over 60 seconds. This prevents false pause/resume cycling in real-world riding scenarios.

⏸️ Auto-Pause Implementation (with position delta) 
// H17 fix + PRD Audit: Auto-pause requires speed=0 AND position delta <5m for 60s

let zeroSpeedTimer: number | null = null;
let zeroSpeedAnchor: { lat: number; lng: number } | null = null;
let continuousAutoPauseStart: number | null = null;

// Haversine distance in meters between two coords
const distanceMeters = (a: { lat: number; lng: number }, b: { lat: number; lng: number }): number => {
  const R = 6371000;
  const dLat = (b.lat - a.lat) * Math.PI / 180;
  const dLng = (b.lng - a.lng) * Math.PI / 180;
  const sin2 = Math.sin(dLat / 2) ** 2 +
    Math.cos(a.lat * Math.PI / 180) * Math.cos(b.lat * Math.PI / 180) *
    Math.sin(dLng / 2) ** 2;
  return R * 2 * Math.atan2(Math.sqrt(sin2), Math.sqrt(1 - sin2));
};

const FORGOT_TO_STOP_NOTIFY_MS = 10 * 60 * 1000;  // 10 min
const FORGOT_TO_STOP_AUTO_END_MS = 30 * 60 * 1000;  // 30 min

const rideLocationListener = (location: LocationObject) => {
  const speedMps = location.coords.speed ?? 0;
  const currentPos = { lat: location.coords.latitude, lng: location.coords.longitude };

  if (speedMps < 0.5) {  // Stationary (< 0.5 m/s ≈ 1.8 km/h)
    if (!zeroSpeedTimer) {
      zeroSpeedTimer = Date.now();
      zeroSpeedAnchor = currentPos;
    }

    // PRD Audit Fix: Check position delta from anchor point
    const delta = distanceMeters(zeroSpeedAnchor!, currentPos);
    const stoppedDuration = Date.now() - zeroSpeedTimer;

    if (delta > 5) {
      // Moved >5m — rider is maneuvering slowly (parking lot, filtering)
      // Reset anchor but keep timer if speed is still low
      zeroSpeedAnchor = currentPos;
      zeroSpeedTimer = Date.now();
    } else if (stoppedDuration > 60000) {
      // Speed <0.5 AND position delta <5m for 60s → truly stopped
      const subState = rideStorage.getString('ride.recording_sub_state');
      if (subState !== 'stopped') {
        rideStorage.set('ride.recording_sub_state', 'stopped');
        continuousAutoPauseStart = Date.now();
      }

      // PRD Audit Fix: "Forgot to Stop" detection
      if (continuousAutoPauseStart) {
        const autoPauseDuration = Date.now() - continuousAutoPauseStart;

        if (autoPauseDuration > FORGOT_TO_STOP_AUTO_END_MS) {
          // 30 min auto-pause → auto-end ride, trim idle tail
          autoEndRide(continuousAutoPauseStart);
          return;
        } else if (autoPauseDuration > FORGOT_TO_STOP_NOTIFY_MS) {
          // 10 min auto-pause → send notification
          showForgotToStopNotification();
        }
      }
    }
  } else {
    // Moving again
    if (zeroSpeedTimer) {
      const pauseDuration = Date.now() - zeroSpeedTimer;
      if (pauseDuration > 60000) {
        // Was in STOPPED; accumulate auto-pause duration via MMKV
        const prev = rideStorage.getNumber('ride.total_auto_paused_ms') ?? 0;
        rideStorage.set('ride.total_auto_paused_ms', prev + pauseDuration);
        rideStorage.set('ride.recording_sub_state', 'moving');
      }
      zeroSpeedTimer = null;
      zeroSpeedAnchor = null;
      continuousAutoPauseStart = null;
    }
  }

  // Always record waypoint (don't skip during STOPPED)
  addWaypoint(location);
};

const calculateMovingTime = () => {
  const { startedAt, totalPausedMs, status } = useRideStore.getState();
  const endTime = status === 'summary' ? endedAtMs : Date.now();

  const totalMs = endTime - startedAt;
  const movingMs = totalMs - totalPausedMs;  -- Exclude paused + auto-paused

  return movingMs / 1000;  -- Return seconds
};

"Forgot to Stop" Detection (PRD Audit Fix)

🔧 PRD Audit Fix

Every mature ride tracker has "forgot to stop" detection. Without it, riders walk into restaurants with rides still recording for hours — this is the #1 support complaint for ride tracking apps.

Trigger Action Details
10 min continuous auto-pause Push notification "Still riding? Your ride has been paused for 10 minutes. Tap to resume or end your ride."
30 min continuous auto-pause Auto-end ride + trim idle tail End ride at the timestamp when auto-pause began (trim 30 min of idle). Show "Ride auto-ended" notification with option to undo.
🛑 Auto-End Implementation 
// PRD Audit Fix: Auto-end ride after 30 min of continuous auto-pause

const autoEndRide = async (autoPauseStartedAt: number) => {
  // Trim idle tail: set endedAt to when auto-pause started, not now
  const rideId = rideStorage.getString('ride.current_id');
  if (!rideId) return;

  // Calculate stats using autoPauseStartedAt as the effective end time
  const startedAt = rideStorage.getNumber('ride.started_at')!;
  const totalPausedMs = rideStorage.getNumber('ride.total_paused_ms') ?? 0;
  const totalAutoPausedMs = rideStorage.getNumber('ride.total_auto_paused_ms') ?? 0;
  const effectiveEndTime = autoPauseStartedAt;

  // Remove waypoints recorded after auto-pause started (idle tail)
  trimWaypointsAfter(rideId, autoPauseStartedAt);

  // End the ride with the trimmed timestamp
  await endRideMutation({
    rideId,
    endedAt: new Date(effectiveEndTime).toISOString(),
    pausedDurationS: Math.round(totalPausedMs / 1000),
    autoPausedDurationS: Math.round(totalAutoPausedMs / 1000),
  });

  // Show notification with undo option
  await Notifications.scheduleNotificationAsync({
    content: {
      title: 'Ride auto-ended',
      body: 'Your ride was automatically ended after 30 minutes of inactivity.',
      data: { rideId, action: 'auto_ended' },
    },
    trigger: null,
  });

  // Clean up ride state
  cleanupRideState();
};

Speed-Based Gradient Polyline

Each waypoint carries speed_mps. The LineLayer uses a data-driven lineGradient expression to interpolate color along the route:

🗺️ Mapbox Gradient Polyline Implementation 
import MapboxGL from '@rnmapbox/maps';

const RideSummaryMap = ({ ride, waypoints }: Props) => {
  // Build GeoJSON with speed as a property per coordinate
  const routeGeoJSON = useMemo(() => ({
    type: 'Feature' as const,
    properties: {},
    geometry: {
      type: 'LineString' as const,
      coordinates: waypoints.map(wp => [wp.longitude, wp.latitude]),
    },
  }), [waypoints]);

  // PRD Audit Fix: Compute color stops by cumulative distance, not waypoint index.
  // GPS waypoints cluster in slow sections (more points) and spread in fast sections.
  // Index-based stops would shift colors incorrectly. Distance-based stops ensure
  // the gradient maps to actual speed at each point along the route.
  const cumulativeDistanceColorStops = useMemo(() => {
    if (waypoints.length < 2) return [0, '#3366e6', 1, '#3366e6'];

    // 1. Compute cumulative distances along the route
    const distances = [0];
    for (let i = 1; i < waypoints.length; i++) {
      const prev = waypoints[i - 1];
      const curr = waypoints[i];
      const d = distanceMeters(
        { lat: prev.latitude, lng: prev.longitude },
        { lat: curr.latitude, lng: curr.longitude },
      );
      distances.push(distances[i - 1] + d);
    }
    const totalDist = distances[distances.length - 1] || 1;

    // 2. Map each waypoint to a color based on speed
    const getColor = (speedMps: number): string => {
      const kmh = speedMps * 3.6;
      if (kmh < 30) return '#3366e6';  // Primary blue — slow
      if (kmh < 80) return '#2d9e78';  // Accent green — cruising
      return '#D4622E';                 // Signature orange — fast
    };

    // 3. Build [progress, color, progress, color, ...] with distance-normalized positions
    return waypoints.flatMap((wp, i) => [
      distances[i] / totalDist,
      getColor(wp.speed_mps ?? 0),
    ]);
  }, [waypoints]);

  const bounds = useMemo(() => ({
    ne: [Math.max(...waypoints.map(w => w.longitude)), Math.max(...waypoints.map(w => w.latitude))],
    sw: [Math.min(...waypoints.map(w => w.longitude)), Math.min(...waypoints.map(w => w.latitude))],
    paddingTop: 60, paddingBottom: 200, paddingLeft: 60, paddingRight: 60,
  }), [waypoints]);

  return (
    <MapboxGL.MapView
      style={{ flex: 1 }}
      styleURL={MapboxGL.StyleURL.Dark}
      logoEnabled={false}
      attributionEnabled={false}
    >
      <MapboxGL.Camera
        bounds={bounds}
        animationMode={'flyTo'}
        animationDuration={1500}
      />

      {/* Route polyline — PRD Audit Fix: lineMetrics + cumulative distance color stops */}
      <MapboxGL.ShapeSource id={'routeLine'} shape={routeGeoJSON} lineMetrics={true}>
        <MapboxGL.LineLayer
          id={'routeLineLayer'}
          style={{
            lineColor: ['interpolate', ['linear'], ['line-progress'],
              // Color stops normalized by cumulative distance (not index)
              // This ensures even color mapping regardless of waypoint density
              ...cumulativeDistanceColorStops,
            ],
            lineWidth: 5,
            lineCap: 'round',
            lineJoin: 'round',
          }}
        />
      </MapboxGL.ShapeSource>

      {/* Start marker (green) */}
      <MapboxGL.PointAnnotation
        id={'start'}
        coordinate={[waypoints[0].longitude, waypoints[0].latitude]}
      >
        <View style={{ width: 20, height: 20, borderRadius: 10, backgroundColor: '#2d9e78', borderWidth: 3, borderColor: 'white' }} />
      </MapboxGL.PointAnnotation>

      {/* End marker (signature orange) */}
      <MapboxGL.PointAnnotation
        id={'end'}
        coordinate={[waypoints[waypoints.length - 1].longitude, waypoints[waypoints.length - 1].latitude]}
      >
        <View style={{ width: 20, height: 20, borderRadius: 10, backgroundColor: '#D4622E', borderWidth: 3, borderColor: 'white' }} />
      </MapboxGL.PointAnnotation>
    </MapboxGL.MapView>
  );
};

Waypoint Upload Quotas & Rate Limiting (H12 fix)

⚡ Quota Enforcement 
// H12 fix: Max 10k waypoints per ride, 10 upload calls/min per user
// PRD Audit Fix: Use @Throttle() decorator (consistent with existing codebase pattern)
// instead of custom in-memory Map (lost on restart, doesn't scale horizontally).
// app.module.ts already configures 'default' and 'ai' ThrottlerModule buckets.

@Injectable()
export class RidesService {
  constructor(
    @Inject(SUPABASE_USER) private readonly db: SupabaseClient,
  ) {}

  // Rate limiting: use @Throttle({ default: { ttl: 60000, limit: 10 } })
  // on the resolver method (uploadWaypoints mutation), not in the service.
  // This matches diagnostics.resolver.ts and articles.resolver.ts patterns.

  async uploadWaypoints(
    userId: string,
    input: UploadWaypointsInput
  ): Promise<boolean> {
    // H12: Per-ride waypoint quota (max 10k) — service-layer validation
    const { count, error: countError } = await this.db
      .from('ride_waypoints')
      .select('*', { count: 'exact', head: true })
      .eq('ride_id', input.rideId);

    if (countError) throw new InternalServerErrorException('Failed to check waypoint count');

    if ((count ?? 0) + input.waypoints.length > 10000) {
      throw new BadRequestException(
        `Waypoint quota exceeded. Max 10k per ride, current: ${count}`
      );
    }

    // Batch insert
    const { error } = await this.db
      .from('ride_waypoints')
      .insert(input.waypoints.map((wp) => ({
        ride_id: input.rideId,
        recorded_at: wp.recordedAt,
        ...wp,
      })));

    if (error) throw new InternalServerErrorException('Failed to insert waypoints');

    return true;
  }
}

Cursor Pagination (H11 fix)

🔗 Cursor-Based myRides Query 
// H11 fix: Replace OFFSET pagination with cursor on started_at

async myRides(
  userId: string,
  motorcycleId?: string,
  limit: number = 20,
  cursor?: string  -- base64(startedAt timestamp)
): Promise<RideConnection> {
  let query = this.db
    .from('rides')
    .select('*')
    .eq('user_id', userId)
    .is('deleted_at', null)
    .order('started_at', { ascending: false });

  if (motorcycleId) {
    query = query.eq('motorcycle_id', motorcycleId);
  }

  if (cursor) {
    const decodedCursor = Buffer.from(cursor, 'base64').toString();
    // PRD Audit Fix: Validate cursor is a valid ISO date (matches articles.service.ts pattern)
    if (Number.isNaN(Date.parse(decodedCursor))) {
      throw new BadRequestException('Invalid cursor');
    }
    // started_at < cursor (for DESC ordering)
    query = query.lt('started_at', decodedCursor);
  }

  -- Fetch limit + 1 to detect hasNextPage
  const { data, error } = await query.limit(limit + 1);

  if (error) throw error;

  const hasNextPage = data.length > limit;
  const rides = data.slice(0, limit);

  return {
    edges: rides.map((ride) => ({
      cursor: Buffer.from(ride.started_at).toString('base64'),
      node: mapRideToGraphQL(ride),
    })),
    totalCount: await this.countRides(userId, motorcycleId),
    pageInfo: {
      endCursor: rides.length > 0 ? Buffer.from(rides[rides.length - 1].started_at).toString('base64') : null,
      hasNextPage,
    },
  };
}

Reanimated SharedValue Pattern (C3 fix)

When lean angle is enabled (v1.1), this pattern prevents the 10Hz sensor updates from triggering React re-renders:

📐 Lean Angle via SharedValue 
// C3 fix: Lean angle flows through Reanimated, not Zustand
// Runs on UI thread, zero React overhead

// PRD Audit Fix: useSharedValue is a React hook — cannot be used in a class.
// Use makeMutable (reanimated v4) for non-component shared values.
import { makeMutable } from 'react-native-reanimated';
import { DeviceMotionEvent } from 'expo-sensors';

class LeanAngleService {
  leanAngle = makeMutable(0);
  private calibration: LeanAngleCalibration | null = null;
  private alpha = 0.3;  -- Low-pass filter coefficient

  async initialize() {
    this.calibration = await getLeanCalibration();
    Gyroscope.addListener((motion) => this.updateFromMotion(motion));
  }

  updateFromMotion(motion: DeviceMotionEvent) {
    const { rotation } = motion;
    if (!rotation) return;

    -- Extract lean from rotation.x (roll)
    const rawLean = rotation.x * (180 / Math.PI);
    const calibrationOffset = this.calibration?.offset ?? 0;
    const adjustedLean = rawLean - calibrationOffset;

    -- Low-pass filter (exponential smoothing)
    const filtered =
      this.leanAngle.value * (1 - this.alpha) + adjustedLean * this.alpha;

    -- Clamp to [-90, 90]
    this.leanAngle.value = Math.max(-90, Math.min(90, filtered));
  }
}

-- Usage in HUD (no re-renders)
const LeanAngleIndicator = ({ leanAngle }: { leanAngle: Animated.SharedValue<number> }) => {
  const animatedStyle = useAnimatedStyle(() => ({
    transform: [{ rotate: `${leanAngle.value}deg` }],
  }));

  return (
    <Animated.View style={[styles.leanMeter, animatedStyle]}>
      {* Visual indicator *}
    </Animated.View>
  );
};
