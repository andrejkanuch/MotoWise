# Fix RevenueCat logOut on anonymous users

## Enhancement Summary

**Deepened on:** 2026-05-28
**Research sources:** RevenueCat SDK docs (Context7), SpecFlow analysis, test infrastructure discovery
**Key additions:** Edge case analysis, test strategy with mock patterns, subscription store considerations

## Overview

RevenueCat's `Purchases.logOut()` throws when called on anonymous users: "LogOut was called but the current user is anonymous". This generates 218+ Sentry events across two issues (MOTO-VAULT-REACT-NATIVE-4 and MOTO-VAULT-REACT-NATIVE-6) and pollutes error tracking.

## Problem Statement

In `apps/mobile/src/lib/subscription.ts:259-270`, `logoutRevenueCat()` calls `Purchases.logOut()` unconditionally. When the auth state changes to `null` (sign-out), this function is called from `_layout.tsx:334`. If the RevenueCat user was never logged in (i.e., still anonymous), the SDK throws an error.

**Current code:**

```typescript
// apps/mobile/src/lib/subscription.ts:259-270
export async function logoutRevenueCat() {
  if (isExpoGo()) return;
  const cleanup = await initRevenueCat();
  if (!cleanup) return;
  try {
    const Purchases = await getPurchases();
    await Purchases.logOut();  // throws if user is anonymous
  } catch (e) {
    console.error('[RevenueCat] logOut failed:', e instanceof Error ? e.message : e);
    captureException(e);  // 218+ Sentry events
  }
}
```

**Trigger scenarios:**
1. User opens app but never signs in (RevenueCat initializes with anonymous user) → app backgrounded → auth state fires null → `logoutRevenueCat()` called on anonymous user
2. App restart where auth session expired before RevenueCat `logIn()` was called
3. Edge case: `loginRevenueCat()` failed silently, user later signs out

## Proposed Solution

Guard `Purchases.logOut()` with `Purchases.isAnonymous()` check. The SDK provides `static isAnonymous(): Promise<boolean>` which returns `true` if the `appUserID` was generated by RevenueCat (not set via `logIn()`).

**Fixed code:**

```typescript
// apps/mobile/src/lib/subscription.ts
export async function logoutRevenueCat() {
  if (isExpoGo()) return;
  const cleanup = await initRevenueCat();
  if (!cleanup) return;
  try {
    const Purchases = await getPurchases();
    const anonymous = await Purchases.isAnonymous();
    if (anonymous) return;
    await Purchases.logOut();
  } catch (e) {
    console.error('[RevenueCat] logOut failed:', e instanceof Error ? e.message : e);
    captureException(e);
  }
}
```

## Technical Considerations

- **`isAnonymous()` failure**: If `isAnonymous()` throws, the catch block handles it — no behavioral change. The error would be a legitimate SDK issue worth capturing.
- **Subscription store state**: The Zustand store (`subscription.store.ts`) relies on `customerInfoUpdateListener` to update after `logOut()`. When we skip `logOut()` for anonymous users, the listener won't fire — but this is correct because an anonymous user has no entitlements to clear.
- **Race condition**: `onAuthStateChange` can fire multiple times rapidly. The existing `initRevenueCat()` singleton ensures only one SDK instance, and `isAnonymous()` + `logOut()` are sequential within the same async call, so no race.
- **No store reset needed**: Anonymous users won't have `isPro: true` in the store, so skipping `logOut()` won't leave stale subscription state.

### Edge Cases (from SpecFlow)

- **Double sign-out**: User taps sign out while `logoutRevenueCat()` is already running. Safe — `isAnonymous()` will return `true` on the second call since the first already completed `logOut()`.
- **`logIn()` raced with `logOut()`**: If `loginRevenueCat()` is in-flight when `logoutRevenueCat()` fires, `isAnonymous()` could return stale state. Acceptable — the catch block handles any resulting error, and the next auth cycle will correct the state.
- **Account deletion flow**: `safeSignOut()` is also called after `DeleteAccount` mutation. Same code path — the `isAnonymous()` guard applies correctly.
