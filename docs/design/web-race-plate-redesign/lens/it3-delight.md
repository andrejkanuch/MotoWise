# it3 · /delight lens — the moments that make the site memorable (research only, nothing edited)

Scope: `lens/SCOPE.md`. World: `apps/mobile/DESIGN.md` ("every bike carries a number plate, and the plate tells you whether it is ready"), `DIRECTION.md` (copper is a verb, triad belongs to state, one diagonal, plain voice, entrance motion only), `PRODUCT.md` (no gamification, no hype, honesty), `reference/delight.md` + `reference/craft-floor.md` (browser surfaces carry the design too).

**Delight thesis.** The site should feel like a logbook kept by someone who cares about the machine: the one shared object (the Bike Plate) tells a true story, the parts the browser draws by itself (caret, selection, scrollbar, tab colour, numerals, print) are in the palette, and the only authored moments sit where a rider acts or gets lost. Nothing celebrates; everything is certain.

Method. Read `design-system.css` (1218 lines), `mv-tokens.css`, `bike-plate.tsx`, `hero.tsx`, `theme-toggle.tsx`, `providers/theme-provider.tsx`, `footer.tsx`, `faq.tsx`, `loader.tsx`, every `not-found.tsx` / `error.tsx` / `loading.tsx` in scope, the marketing layout, the checkout success page, the garage (`garage-cards.tsx`, `empty-garage.tsx`, `garage-view.css`), the rider/share/explore/trips surfaces, and grepped every `BikePlate` call site, every number-formatting call site, and every browser-surface property.

## Already earned — keep as is

- **The FAQ "+" quarter-turns into "×"** (`faq.tsx`, display face, 0.3 s) — one line of CSS, no JS, and it is in the condensed face so it belongs to the plate lettering.
- **The 404's route-to-X drawing** (`app/not-found.tsx:107–138`) — authored SVG in tokens, static. Do not add a stroke-draw: not transform/opacity.
- **`.mv-link` hover** — colour step on the underline (`--mv-copper-border` → `currentColor`). Quiet and specific.
- **The footer wordmark's outline** (`.mv-footer-wordmark`, 1px `--mv-line-step` stroke, aria-hidden) — decoration the direction explicitly permits. Do not make it copper (copper is a verb) and do not let it move.
- **The hero strip** (`hero.tsx:139–149`) sets four words in the figure face. It reads like a stat row without claiming numbers; leave it. Do not put figures in it (one stat row per page, and the proof row already holds the honest ones).
- **Explore search** already has ⌘K, arrow keys and `<kbd>` hints (`explore-search-bar.tsx:192, 419–452`); the QR handoff's Copy already reads "Copied" for 2 s (`qr-handoff.tsx:11`). Certainty, not celebration — correct.
- **The empty garage's preview plate** (`empty-garage.tsx:85–109` + `.gv-preview-plate`): a graphite plate with blank bars inside a dashed frame. This is the right empty object: a plate with nothing printed on it yet.

## Rejected — with the reason

| Candidate | Verdict |
|---|---|
| 404 as an "unregistered" plate | Reject. The plate is a bike's readiness; a plate with no bike has no state, and the triad belongs to state (rule 2). A joke on a failure also trivialises being lost. The route-to-X already carries the moment. |
| A plate on the rider's public profile (`app/rider/[username]/page.tsx:123–140`) | Reject. Readiness and the garage index (the racing number) come from private maintenance data the public profile query does not expose; a plate without a true state, or a number invented on the web, is fiction. The hairline bike rows are honest. |
| Bone "No bike yet · add one in the app" plate in empty states (garage, rider with no rides, explore no results) | Reject. Bone = ready, which an empty garage is not. The current graphite preview plate is more truthful; the rider/explore empties ("No saved routes yet", "No routes match these filters") already lead with the next action in plain voice. |
| Racing numbers as section markers / the `.mv-plate-chip` as a section motif | Reject. Rule 5 bans section numbers; craft-floor allows them only when the sequence carries information. `.mv-plate-chip` exists in CSS and has zero call sites — a candidate for /distill, not for spreading. |
| Copper underline that draws on hover for `.mv-link` | Reject. A background-size underline reveal is the generic SaaS gesture; the world's hover is a colour step, already in place. |
| Odometer-style rolling digits on the plate | Reject. A loop, and the plate figure must read instantly. |
| Stroke-dashoffset "draw" of the 404 road | Reject. Motion guardrail: transform/opacity only. |
| The copper loader ring vs a plate skeleton (`loader.tsx`, `.mv-loader`) | Not a delight call. The loader runs three infinite loops (ring, reverse tread, breathing hub) and is a compass-wheel leftover from the editorial world; it is the only indeterminate loop the site needs (Pro activation, GPX export), so trim it to one copper arc on the hairline ring — hand to /animate. A plate skeleton would be wrong there: nothing plate-shaped is loading on /pro. In the garage, `BikeHeroSkeleton` (`garage-cards.tsx:364–376`) could reuse the preview plate's anatomy (figure bar, caption bar, rule, edge bar) instead of a 168 px block so the loading plate has the shape of the plate that replaces it — a /polish note, not a memorable moment. |
| Gradient text, glows, confetti, badges, streak counters, "Pro unlocked" fireworks on checkout success | Reject by contract (PRODUCT.md no gamification; DIRECTION rule 1 no copper glow; brand "rugged, confident, no hype"). The settling plate is the celebration. |
| Sound or haptics anywhere on the web | Reject. No consent, no mute handling, nothing to gain. |
